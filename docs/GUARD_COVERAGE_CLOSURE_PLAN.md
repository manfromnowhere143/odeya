## Proven closure methods

### Harness self-tests and attribution meta-proofs

ADRs 0080 and 0081 factor malformed-case, mutation-failure, safe-reference,
and attribution-harness guards into explicit in-memory self-tests. ADR 0083
makes the attribution self-tests themselves load-bearing across all six
attribution suites. Terminal self-test refusal lines remain named residue when
one more injection layer would only reproduce the same assertion recursively.

### Stable suite-reported refusal

ADR 0104 replaces nonzero-exit credit with the v0.2 proof contract. Each
mutation must compile; the mutated suite must report refusal with exit 1,
non-empty output, and no traceback; the restored control must pass; and an
identical repeat must produce the same SHA-256 fingerprint over the exactly
framed return code, stdout, and stderr. The fingerprint is retained in the
proved row. Empty output, tracebacks, every other exit or signal, recovery
failure, and unstable repeats stay unproved. The predecessor-profile checker
runs serially after the fixed four-worker pool so its nested successor check
does not compete with the successor audit. That schedule is an exclusive-writer
assumption, not a hostile-process sandbox.

### Artifact-mutation vocabularies

ADR 0082 proves the pattern for once-loaded static records: mutate a deep copy
through a closed operation vocabulary, require the intended exact refusal, and
ablate the generator before retaining the case. Apply it to each remaining
inventory, map, disposition, or identity record only after pinning the record
shape and mutation/reason matrix.

### Targeted domain cases

Cross-field comparisons, file-to-file equality, Git-derived lineage, and
resolver semantics need cases constructed from their own predicate. Each case
must be shown to trip the intended guard before retention and then enter the
same refusal-attribution census as its suite. A guard genuinely unreachable
without corrupting the safe baseline stays explicitly unproved; it is not
rounded into coverage.

## Order of work

1. Close remaining mechanical harness and once-loaded-record guards where the
   proven patterns apply without changing domain semantics.
2. Prioritize the highest open domain strata—first-slice, constitutional,
   projection, mathematical, cognitive, physical, the 97 explicitly unproved
   `product-identity-profile-candidate` refusals, the 48 explicitly unproved
   `product-identity-profile-0.3-candidate` refusals, and the 127 explicitly
   unproved `prq-002-identity-cohort` refusals—by consequence, not only raw
   count. The PRQ-002B and PRQ-002E suites' retained safe/known-bad cases and
   PRQ-002A's 47 retained safe/known-bad cases do not by themselves establish
   mutation coverage beyond the exact measured guard rows.
3. Retain targeted cases for reachable domain guards and name the exact reason
   for any intentionally unproved terminal residue.
4. Treat the 81 unproved human-decision-assurance refusals as real open
   evidence work. Prioritize them by consequence, retain exact one-intent cases
   only where they prove the intended guard, and do not infer wrapper coverage
   from the underlying candidate-evidence evaluator.
5. Re-run the generalized mutation audit on every checker change; update this
   table only from the retained machine record.

## Boundary

Statement reachability is not correctness. A proved guard is exercised; it is
not shown to encode the right rule. The audit's discovery grammar is itself a
known limitation and must be extended before a new refusal construct can enter
the denominator. The generalized proof does not identify the exact case that
reached a guard, exclude every non-traceback startup-failure mask, resist a
hostile concurrent writer, sandbox suite processes, or constitute independent
reproduction. Nothing here is an accountable review determination, an admitted
member, independent implementation evidence, or Gate A acceptance.
